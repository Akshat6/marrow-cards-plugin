# Daily Quest — permanent new-chat handoff (phase one)

**Decision date: 2026-10-24.** This is the canonical operating contract for the **third view inside the existing `marrow-cards` Obsidian plugin**. The user authorized making it live. The original PYQ Review (often TPYQ), Dynamic Recall, their notes, AI modes, saved grades and all existing approved source content must remain independent.

1. Read [public AGENTS.md](../AGENTS.md), [plugin-maintenance.md](plugin-maintenance.md), **this document**, and live `main.js`, `manifest.json`, `tests/daily-quest.js` and `styles.css` from `Akshat6/marrow-cards-plugin/main`.
2. Read the PRIVATE `Akshat6/marrow-cards-data/AGENTS.md`, `daily-quest/README.md`, `daily-quest/policy.json`, `manifest.json` and all relevant active `packs/*.json` using the connected GitHub app. If investigating source PYQ eligibility, read the live connected Google Sheet “Marrow PYQ Index Master” and the user-provided original `Year wise pyq.pdf`. Do not assume old counts remain current.
3. Distinguish **an approved source card**, **a mapped source PYQ without a complete usable card**, and **a Knowledge Unit**. Do not publish private question/answer text in public code/docs or invent missing original figures/tables.
4. For **index/schedule/goal/interval** changes, edit PRIVATE policy JSON after the user's instruction, increase `version` and verify readback. The student taps Daily Quest → **Update selection rules** in Obsidian; this affects **new daily plans only**. For UX, scheduling algorithm, data model or feature changes, edit PUBLIC plugin code/tests and ship a tested BRAT release as in maintenance guide.
5. For each code release, confirm GitHub Actions for the exact head SHA passed, merge/release, verify GitHub release assets, then request real phone/tablet smoke tests. Preserve all vault data. Never silently modify source packs or historical logs.

**Short prompt for a new chat:** “Read `Akshat6/marrow-cards-plugin/AGENTS.md` and `docs/daily-quest-handoff.md`, plus the private `marrow-cards-data/daily-quest/README.md` and live policy. Continue Daily Quest [requested change]; keep Phase 1 PYQ-only, preserve saved attempts and other modes, run tests, and publish only with release verification.”

## Product decision — Phase 1

- **Up to 10 original, approved PYQ MCQs per local calendar day**, one 10-card session. User deliberately chose this small habit: approximately **30 distinct PYQs across the first three days**, rather than 30 questions every day.
- **No Knowledge Units whatsoever** in Phase 1, regardless of their Verified/Source-extracted/Needs Review labels; they were designed as input for Groq, not as fixed multiple-choice questions. No on-demand Groq, prompts, API keys, typing or generative MCQs. Only existing `type:'pyq'` cards with approved status, source options and a safely resolvable answer are eligible. Fact cards, source-incomplete or unverified answers and unmatched-key items are excluded.
- The student's initial whitelist: `ANAT-R3-067`, `068`, `069`, `070`, `074` (Anatomy Thorax and Mediastinum); `PED-RESP-04` (Cystic Fibrosis); `MED-PULM-01` through **`MED-PULM-08` inclusive** (ending with Respiratory Failure and ARDS). Other indices, `INT-PULM` alias-only cards, `MED-PULM-NA`, excluded Medicine subtopics and later Medicine indices are not eligible. Selection tests **source `indexIds`** against this whitelist, not names or Integrated aliases.
- As checked against the LIVE private manifest on 2026-10-24, **32 approved cards** met both the index scope and MCQ-safe-answer eligibility: Anatomy **12**, Pediatrics **4**, Medicine **16**. The mapping Sheet lists some incomplete items; do not confuse it with an installed full-MCQ count.
- The three notable **mapped but unpublished/incomplete** source PYQs are `I22-MED-Q003` and `I23-MED-Q017` (the missing pre/post bronchodilator PFT tables, explicit archival in private `exam-intelligence/pulmonology/practice/excluded-source-questions-v1.json`), and `I23-PED-Q014` (missing numbered statements i–iv in the source PDF, page 5718; no recorded formal rejection reason was found). Exclude all three from Daily Quest; don't manufacture those source data. This list is not exhaustive of every excluded PYQ in the wider source.
- Two active Medicine cards in the initial count carry source home indexes differing from the master workbook (`A17-MED-Q037` and `N21-MED-Q008`). Do **not** remap/edit automatically just to make counts match. A separate source-backed index reconciliation is needed if asked.

## How a daily review works

1. Student opens **Open Daily Quest** in the Obsidian command palette or sparkles ribbon icon. The dashboard displays progress, a practice streak (currently counts a day after **2 or more** rated items, not necessarily ten), and **Start 10 cards** / **Continue**.
2. On first Start in a local date, candidate pool is built from locally downloaded approved packs. **Never-seen-in-Daily-Quest items get first priority** until initial coverage finishes, so 32 eligible PYQs yield ten distinct questions on each of the first three days if the student completes those sessions and no new items are added. After that: independently graded **Again** items become due after `weakDays=1`, **Got it** items after `goodDays=4`. Not-yet-due repeats aren't inserted to pad the target. This is a simple spacing heuristic, not a scientifically calibrated algorithm.
3. Daily plan stores deterministic, ordered **stable PYQ IDs only**; the plan remains fixed for the current date even if the whitelist or private policy changes. If the user adds approved indexes, the next new date's plan automatically includes those source-index PYQs after refreshing card packs and policy.
4. Each MCQ displays the original question, answer choices **in source order (no shuffling)**, and downloaded figures. Tapping an option grades the choice exactly once and shows answer/explanation; the card remains until **Next card**. Alternatively the user can tap **Reveal answer** and self-grade Again/Got it. There is no KU text question. After ten (or fewer due cards), return to the completion dashboard.
5. All outcomes are **separate from original PYQ Review and Dynamic Recall**. Daily Quest may use only its own prior ratings for future interval selection; it does not add fake Right/Wrong or Groq 0–10 scores. No question/answer text or proprietary media is copied into local outcome logs.

## Code, policy and storage

- Public code: `main.js`: `DAILY_QUEST_VIEW_TYPE`, `DAILY_QUEST_POLICY`, `validateDailyQuestPolicy`, `dailyQuestCandidatePool`, `dailyQuestPriority`, `dailyQuestSelect`, `dailyQuestAppend`, `MarrowDailyQuestView`. Styles under `.marrow-daily` in `styles.css`. Regression `node tests/daily-quest.js` plus all existing tests in GitHub Actions. Don't create a separate plugin ID or separate app.
- **Private authoritative remote policy:** `Akshat6/marrow-cards-data/daily-quest/policy.json`, currently `version=1.1.0`, `goal=10`, `pyqTarget=10`, `blockSize=10`, `weakDays=1`, `goodDays=4`, and the exact whitelist above. Local fallback in public `main.js` matches these defaults. `pyqTarget===goal` is a Phase 1 **hard validation invariant**; a policy change cannot sneak KUs back into the pool.
- **Local policy cache:** `MarrowCards/daily-quest/policy.json` — may be absent before the first successful manual Update selection rules. Remote failure leaves local cached/default policy in place. Existing plan is not rerolled.
- **Daily plan (vault):** `MarrowCards/daily-quest/days/YYYY-MM-DD.json`.
- **Append-only per-device attempts (vault):** `MarrowCards/daily-quest/attempts/<device-id>/YYYY-MM.jsonl`. Events contain ID, `type=graded`, `itemKey=p:<stable-card-id>`, `grade=good|again`, local `day`, ISO `at`, `deviceId`. No private medical text. Month filename uses UTC timestamp; day inside event is local calendar date.
- Existing `MarrowCards/packs`, `media`, `notes`, `reviews`, `dynamic-recall`, `.obsidian`, private source manifest and user attempts remain untouched. Syncthing can carry the new vault `daily-quest/` files; avoid simultaneous edits on both phone/tablet before sync finishes and keep **`.obsidian/` excluded**. A plan is shared by vault, whereas attempts are written in device-ID-specific folders. No cloud plan arbitration or phone/tablet real-time lock exists.
- Current Daily Quest itself **does not upload grades to private GitHub**; future chats cannot infer Daily Quest attempt history from the private policy or Dynamic Recall progress snapshots. Ask for a local exported copy if an audit of Daily Quest grades is requested. The connected GitHub app can update the remote policy, not automatically read phone-only vault attempts.

## Safe expansion path

- Adding another **existing approved PYQ index**: read source map/pack status, confirm index ID and user scope, then add ID to private `daily-quest/policy.json` with incremented `version` and verify; user refreshes PYQ packs and taps Update selection rules. No plugin code or new medical text needed. Only next day's plan uses the added index.
- If user later wants **30 per day in three 10-card sessions (still PYQ-only)**: after adequate approved pool, policy `goal=30, pyqTarget=30, blockSize=10` is accepted; existing block/navigation UI handles it. Test on device.
- KU introduction is **not scheduled automatically after a month**. First verify/create a bank of **static, medically/source-checked MCQ cards**, with properly formed choices and source IDs. The raw dynamic KU fields cannot be selected as if they were ready MCQs. This requires a new source eligibility/approval workflow and likely a plugin code + UI release; never simply set `pyqTarget<goal` under the current policy validator.
- Policy changes cannot implement alternative ranking, hidden questions, notifications, AI or graded score sync. Those require explicit code changes. Do not create background reminders automatically.

- Rollback code through a known previous BRAT release; **do not delete existing Daily Quest days/attempts, notes or PYQ histories to roll back**. A code rollback and vault backup are different operations.

## What not to confuse with Daily Quest

TPYQ is the original deeper PYQ reviewer and may shuffle independent options. Dynamic Recall grades KU free recall using Groq and maintains a distinct source-verification status; Experimental PYQ-style creates **unverified model-generated** questions. **Daily Quest Phase 1 is none of those:** no AI, no KUs, no synthetic practice questions, no independent repository of source content, no changes to canonical approved PYQ status.
