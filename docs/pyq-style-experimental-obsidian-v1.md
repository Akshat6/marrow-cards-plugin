# Experimental AI MCQ integration — initial user-accepted scope (development)

**2026-10-22.** The user considered the two genuinely Groq-generated source-backed questions decent and requested Obsidian integration while offline PYQ analysis grows. This is a specific **opt-in personal experiment**, not independent clinical verification or permission to turn every reviewed hypothesis into a medical question.

An independent `Try one Experimental AI MCQ (unverified)` action in the PYQ-style home/index screen downloads a separately versioned **private** experimental intelligence feed from `exam-intelligence/experimental/ai-mcq-study-v1.json` using the plugin's existing read-only GitHub token. It verifies every complete Verified KU excerpt, original source index, answer and locator against the locally downloaded original feed. A blueprint has exactly one `homeIndexId` for display and may preserve two or three original `sourceIndexIds[]`. Held/unapproved relationships are absent from this opt-in feed. Original source KUs are never reindexed or copied into PUBLIC code.

Each click selects a reviewed user-accepted relationship and calls the existing one-request, quota-metered Groq model; no auto-retry or paid fallback. It validates Groq's exact A–D option/key/rationale and KU citation structure, stores the raw parsed response and source packet in **separate private device-local** `experimental_candidate_unverified` events before showing the item, and labels the question as **not independently medically verified**. The learner taps an option, sees the model's key and per-option explanation, and can flag it; `experimental_answered` records explicitly do not alter Verified scores or legacy question histories. Any invalid or unable-to-construct response is rejected, preserved when available, and not displayed. No images are used.

The existing separate **clinically reviewed approved-runtime** feed, original historical PYQ Review, Dynamic Recall, source cards, approved media, analysis reports, device identities, manifest and releases are unchanged. The first private experimental feed includes **006** and **068** only; `050` remains rework, `060` hold, `067` a possible candidate awaiting review. New subjects require additional verified KU analysis and separately reviewed/versioned private experimental feed entries.

The test `tests/pyq-style-experimental-integration.js` uses only invented tokens, synthetic KU IDs, a mocked provider and device vault. GitHub CI establishes source/structure/controller compatibility only; device UI, network/quota and medical-answer acceptance still require actual user testing. **This development branch is not a BRAT or main release.**
