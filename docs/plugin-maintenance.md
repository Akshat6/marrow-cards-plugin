# Marrow Cards — plugin maintenance and upgrade guide

**Purpose:** A future ChatGPT session or developer can safely maintain the Obsidian plugin **without access to previous chats**. This file covers **plugin/UI/code** changes. For extracting and approving new PYQs, follow [flashcard-workflow.md](flashcard-workflow.md). Both workflows start at [../AGENTS.md](../AGENTS.md).

_Updated: 2026-10-18, for direct v0.3.0 Dynamic Recall release; device validation remains pending._

## 1. Re-read live source and preserve boundaries

- Public **plugin/code** repo: `Akshat6/marrow-cards-plugin` (this repo), main branch; principal files `main.js`, `styles.css`, `manifest.json`, `tests/smoke.js`, `README.md`, `AGENTS.md` and `docs/`.
- **Private approved content** repo: `Akshat6/marrow-cards-data`. Always read its live `manifest.json` and relevant packs before reasoning about actual card structure/counts. It contains catalog, approved fact/PYQ card packs and source images. **Never** copy PYQ text/options/images, personal notes, tokens or review logs into this public code repo, even as regression fixtures.

## 2. Existing user-visible contract — preserve unless specifically requested

**Navigation:** `MBBS → Subjects → System/subheading → Indexes` using the actual `system` field from the local approved index catalog. Subject and system sections are one-at-a-time accordions. Checked indexes persist across sections and can be reviewed or browsed together. One-index **Review** or **Browse** beside a tile acts on *only that index*. The **Review selected indexes (N)**, **Browse selected indexes (N)** and neutral **Clear all selection** controls appear together at the top and bottom of the subject list. Clearing resets only `this.selected` across all subjects, redraws to update counts/checkboxes and restores subject-list scroll; it never touches review history, card packs or notes. Purple Review / neutral Browse; no old 110px Android gap. The "Show only indexes with approved cards" filter hides empty indexes, systems, and subjects without removing any selected IDs or packs. Longer accordion panels remain scrollable.

**Review:** `startReview` → `startSession(..., 'review')` → `resetQueue` → `present`. `present` records `seen` to device-local JSONL once per displayed review card. `Ever wrong` filters cards ever marked wrong; `Never seen` filters never seen. For manually graded cards, flip (reversible) then tap Right or Wrong; `grade` records exactly one result and advances. A flipped card is *not* automatically counted wrong.

**MCQ tap-to-grade:** On a Review card whose source correct option can be safely resolved, options render as tappable buttons. `correctOptionIndex(card)` resolves **original index**. `canShuffleCard(card, correct)` conservatively disables shuffling for positional/relative choices, image marker labels, sequence answers, or letter-dependent explanations. `shuffleChoiceIndices` chooses a display permutation **once per presentation**; option identity stays tied to the source index, not currently shown letter. Clicking calls `selectOption(sourceIndex)`: logs Right/Wrong **once**, flips automatically, keeps explanation and **My notes** available, then requires **Next card** (`nextAfterOption`) to advance. `Show question` should not allow regrading. `Flip to answer` + manual Right/Wrong continues to work if the user wants mental recall. If the original answer cannot be verified, options remain read-only and manual flipping is the safe fallback. Fact cards without options remain manual.

**IMPORTANT v0.2.4 answer-format regression:** Newly published OPH-32 and OPH-33 PYQ packs use correct answers such as `B — Example` and `A\n1 — First ...`. The v0.2.3 `correctOptionIndex` parser accepted `B. Example` but not the Unicode em/en dash or a multiline numbered answer, leaving Review options unclickable even though the original choices and answer were valid. `comparableOptionText` now normalizes whitespace, list punctuation and dash variants for **full option-text matching**, while `correctOptionIndex` requires the claimed letter to match its corresponding option; mismatched text remains manual-only. Numbered sequence options never shuffle. Regression tests exercise rendered option buttons across sequential mixed-format synthetic MCQs, preserve single grading, and verify mismatch/Browse fallbacks. No approved card JSON or private manifest change is required.

**IMPORTANT v0.2.3 regression:** v0.2.2 rendered next-card MCQ buttons with `option.disabled = Boolean(this.answerState) || this.busy`. Because `nextAfterOption` (and manual `grade`) called `present` while `busy` was still true, next-card DOM buttons stayed disabled **even after** busy became false. That made the first of a three-card index work but later cards unresponsive. The fix uses `option.disabled = Boolean(this.answerState)` and keeps the **live** `this.busy` guard inside `selectOption`. **Never bind a long-lived DOM disabled state to an ephemeral async transition flag without re-rendering when it clears.** The sequential three-card and post-manual-grade tests in `tests/smoke.js` catch this exact failure.

**Browse:** `startBrowse` → `startSession(...,'browse')`. No `seen`, Right, Wrong, accuracy changes or clickable answer options. The UI offers Previous / Show answer–Show question / Next, preserving *original* source option order. `My notes` works in Browse and Review, including after flipping/answering.

**Personal notes:** Every card has `My notes (type / pen)`. Notes are **local** under `MarrowCards/notes/<stable-card-id>/text.json` and `ink.json`, separate from downloaded `packs/`, `media/` and per-device `reviews/<device-id>/*.jsonl`. Typed text + vector ink are two editable layers on the same fixed 720×960 page; quick shorthand typing works on narrow phones, stylus pen/whole-stroke eraser/undo on tablet, autosave plus manual save, and pending writes flush on navigation. These files sync through **Syncthing**, not GitHub. Do not reset, move, delete or overwrite existing notes or review events for a plugin/UI upgrade. Avoid editing on two devices before the vault finishes syncing; file versioning/backups are recommended but optional. `.obsidian/` remains excluded from Syncthing on both devices.

**v0.2.10 Clear all selection:** Both top and bottom multi-index action groups include **Clear all selection**. They are disabled when `this.selected` is empty, including after clearing. One click clears the complete selection Set, regardless of collapsed subheadings or the approved-only filter. Redraw the subject hierarchy so *all* selection counters, visible checkboxes, and Review/Browse disabled states update together. Preserve current subject/subheading expansion, filter and scroll position. Do not invoke review/Browse or mutate note/media/review data. Synthetic regression tests verify top and bottom buttons, cross-subject + cross-subheading selections, disabled states, scroll restoration, and unchanged reviewed-card accuracy. The previous v0.2.1 regression test expecting exactly two action buttons must now expect three.


**v0.2.7 index Questions and accuracy layout:** Keep the source hierarchy MBBS → Subject → System/subheading → Index. `drawIndexChoices` renders Review/Browse and an additional **Questions** button per index; clicking it expands **only** `getQuestion(card)` statements and each card's local **Seen, Right, Wrong, Accuracy**. It must not include options, answers, explanations, original figures or IDs. The index tile displays cumulative `indexReviewTotals(cards, this.plugin.stats)`, with **accuracy = sum(Right)/(sum(Right)+sum(Wrong)** across approved cards for that specific index; no attempts produces `—`. This is read-only: no `recordEvent` calls; don't alter the private card packs, history or notes. The per-card stats line is deliberately removed from `MarrowCardsView.draw()` in Review/Browse, but card grading/filtering and note features remain. `tests/smoke.js` uses synthetic secret options/answers/explanations/images to assert the list cannot expose them, tests 100% / 25% / —, weighted 50% index accuracy, zero cards, hide/show, modern subject accordion and unchanged review logs. Do not reintroduce per-card stats during review unless explicitly asked.

**v0.2.6 pen-color and image layout:** `NOTE_PEN_COLORS` supplies six discrete, accessible color swatches in `MarrowCardsView.drawNoteEditor`; selecting a color switches to Pen and stores the device's current choice in its plugin settings. Every new vector stroke owns its color and old strokes remain unchanged. `image.json` optionally contains `placement:{x,y,width,height}` in CSS pixels on the fixed 720x960 page. `noteImagePlacement` provides an old-file fallback while `validNoteImagePlacement` validates all persisted dimensions and bounds. The Move / resize image control enables touch/stylus/mouse pointer gestures on a frame above the pen canvas; drag moves the image and the bottom-right handle resizes proportionally without changing existing strokes or images in `MarrowCards/media`. `saveCardNoteImagePlacement` writes geometry to the card-local image metadata only, with filename checking to avoid overwriting a newly replaced image. `flushNote` saves pending geometry on navigation. Image positioning is independent of note ink, so tell the user to position before annotating. Tests cover v0.2.5 geometry fallback, swatch choice, a saved red stroke, drag/resize, bounds, persistence, and no writes to approved media/reviews. Real Android gestures need device validation.

**v0.2.5 image-backed personal notes:** The reader supports two sources in Browse and Review: **Use question image** for an already-downloaded `MarrowCards/media/<name>` source and **Choose image from device** (file input; PNG/JPEG/WebP up to 15 MB). The source is **copied**, never edited. `MarrowCardsPlugin.addCardNoteImage` validates magic bytes and size, creates `MarrowCards/notes/<card-id>/images/note-<id>.<ext>`, then writes `image.json` with that filename. `readCardNote` returns an optional image reference; older notes without `image.json` still work. The note editor draws an absolutely positioned image behind text and vector ink on the original 720x960 page; with an image, type below it. Removing the image writes a null pointer but intentionally leaves the image file and all handwritten/typed notes alone. One picture is displayed per note page; replace it to use another. Sync the entire notes folder recursively through Syncthing. Missing image assets are shown as missing rather than deleting metadata. Test on actual Android phone/tablet for file picker, display scaling, note reopen, Pen/Erase and screen navigation. **Never update the private data repo or rewrite `MarrowCards/media` for this feature.**

**Device startup:** `onload()` registers views/settings/commands synchronously *before* async `initializeRuntime()`; this prevents the original Android cold-start issue where the settings tab disappeared. Do not reintroduce old pilot cleanup on startup or block registration behind vault I/O. Plugin code updates are distributed with **BRAT separately on each device**; card pack refresh uses Check GitHub / Refresh local, then Syncthing for the vault. The phone's private read-only GitHub token belongs in local Obsidian SecretStorage and **never** in chat or synced files.

## 3. Source areas and smoke/regression tests

- `main.js`: data schema guard `validatePack` / `isCard`; `correctOptionIndex`, `canShuffleCard`, `shuffleChoiceIndices`, `tally`; `MarrowCardsPlugin` for sync, notes, review logs; `MarrowCardsView` for hierarchy, queues, notes, MCQ presentation and grading; `MarrowSettingsTab` for local options/token.
- `styles.css`: mobile navigation, longer accordion and nested systems; scrollable review body + docked footer; full-width MCQ options; text/ink editor. Avoid accidental overlarge margins, flex/grids that hide buttons behind Android/Obsidian navigation, and overriding touch scrolling.
- `tests/smoke.js`: Node/VM syntax and data checks, Android startup registration, independent question scrolling and flip-back, collapsible subject/system selection, availability filter, Browse no-grade, text/ink note persistence, MCQ shuffle and tap-to-grade, and **multiple consecutive MCQs after auto and manual grading**. Run `node --check main.js && node tests/smoke.js` (the GitHub Actions publish workflow also runs checks).
- When fixing an issue that appears only after moving from card 1 to 2/3, **test the actual DOM buttons and their `disabled` flags on card 2 and 3**, not only direct method calls on the first card. Verify review-event counts are exactly correct; never generate duplicate Right/Wrong events on flip-back, tapping twice, or returning from notes.
- For data-sensitive MCQ edge cases, test synthetic dummy options in the **public** repo. You may privately validate the real approved pack through connected GitHub, but do not commit its original question text to tests.
- Additional high-value tests: answers encoded as `C. Text`, bare `C`, mismatched answer text, numeric sequence, "Both A and B", `a) A` image-label choices, notes opened after selecting an option, end-of-queue, previous/next Browse and selected multi-index review.
- Automated tests are **not** a substitute for testing touch responsiveness, stylus drawing, scrolling and BRAT restart on the actual Android phone/tablet. Be honest about what was and wasn't device-verified.

## 4. Safe upgrade & release procedure

1. Fetch live `main.js`, `styles.css`, `manifest.json`, `tests/smoke.js`, README and this guide. Identify the smallest change, preserve existing behaviour, and check current private data packs only where relevant.
2. Implement code/UI fix in the public repo. Add/update tests for the **actual reported sequence**, not just a helper. GitHub Actions may run on each commit with the current manifest version; investigate any failure and correct it.
3. Verify **latest code commit** passed GitHub Actions before release. Confirm that no cards, media, manifests, local notes/reviews or tokens were rewritten.
4. Update README, this guide, and relevant AGENTS links for new behaviour and known limitations. Keep all versions current.
5. **Only then** bump public `manifest.json` to the next semantic version. The existing GitHub Actions workflow validates assets and publishes the release for BRAT (with `main.js`, `manifest.json`, `styles.css`).
6. Verify the release is actually **published**, has all three assets, and the release commit's GitHub Actions run succeeded. Don't announce a release on a successful git commit alone.
7. User updates each installed device via **Obsidian → BRAT → Check for updates**, restarts/reopens the reviewer, and checks the affected screens. Describe what still needs real-device validation.

**Manifest-last rule clarification:** The **private data** `manifest.json` is updated last when publishing **approved packs**. A **public plugin** version bump is the last code-release step and does **not** require altering any private data repository manifests.

## v0.3.5 — coverage-first study rounds and ten-percent AI forecast buffer

- For each selected **source index** or explicitly linked Integrated collection, calculate the minimum number of graded attempts across its verified, stable KU IDs. Eligible KUs in the **current round** have exactly this minimum; all other KUs are held until each eligible KU has been scored once. `dynamicRoundPlan(units, stats)` returns `round=minAttempts+1`, `completed`, `remaining` and weak/due-sorted `eligible` units. Only `eligible.slice(0, requestedCount)` enters the question queue.
- **Sessions stop at round boundaries**: if 31 KUs have 20 first attempts, requesting 25 produces an 11-KU session. The *next* session starts Round 2, with low scores selected early *only within* that round. Each round likewise completes every KU's Nth attempt before the N+1th. No deliberate early-repeat percentage; user prioritized 100% initial coverage.
- Existing append-only graded attempts give counts; a **manual score override is not an additional attempt**. Older category-only attempts count, but receive no invented numeric score. Read all device history after restart as before; synced histories and stable KU IDs remain intact. New private KU IDs begin with zero attempts and are prioritized before well-repeated KUs. Do not store separate potentially unsynced round state.
- The UI shows per-index and Integrated collection progress (Round N · x/y scored · z remaining), and caps the 10/25/50/75 buttons to **remaining eligible KUs**, not entire pool size.
- Usage prediction uses `Math.floor(rawEstimate*0.90)` instead of `*0.75`; 20 raw → 18 displayed. Neither formula guarantees live provider quota. Leave local 75-grade/125-request safety caps and no-paid-fallback behavior intact.
- Regression checks must test multiple sessions (25+6 then 31 for a 31-KU pool), Round 2 low-score-first ordering, round-boundary stopping, older categorical histories, mid-round Obsidian reopen and new-KU catch-up. Keep legacy PYQ Review unmodified.
